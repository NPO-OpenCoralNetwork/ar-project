## 動かす

```sh
npm ci
npm run dev            # 開発サーバー（--host 付き。同じ LAN のスマホから開ける）
npm run build          # 型チェック＋ dist/ へビルド（GitHub Pages に公開されるもの）
npm run build:artifact # 夢の旅（yume.html）だけを1つの HTML（dist-artifact/index.html）にまとめる
```

公開: `.github/workflows/yokai-pages.yml` が GitHub Pages に出す（リポジトリの Settings → Pages → Source が「GitHub Actions」のときだけ。まだなら、ビルドの確認だけで終える）。

| URL | 中身 |
|---|---|
| `https://npo-opencoralnetwork.github.io/ar-project/` | 本番（main）の入口。夢の旅は `yume.html`、現の旅は `utsutsu.html` |
| `https://npo-opencoralnetwork.github.io/ar-project/preview/` | 確認用。いちばん新しく更新された `claude/**` ブランチ（どのコミットかは `preview/version.txt`）。夢の旅は `preview/yume.html`、現の旅は `preview/utsutsu.html` |

- Pages のサイトはリポジトリに1つだけなので、公開は必ず main の上で行い、main と確認用のブランチを1つにまとめて出す。`claude/**` へのプッシュは、ビルドを確かめてから main の上の公開を呼び出す。
- 本番と確認用は同じオリジン（`npo-opencoralnetwork.github.io`）なので、`localStorage` の保存（進み具合・テスト用の土地）と、位置・カメラの許可は両方で共通になる。
- HTML は最大10分ほどキャッシュされることがある。新しくならないときは読み込み直す。

## データを作り直す

```sh
node scripts/fetch-osm.mjs   # OpenStreetMap → src/data/iwakuraji-osm.json（--offline で手元の生データから）
node scripts/fetch-dem.mjs --skip-skyline  # 地理院の標高タイル → src/data/iwakuraji-dem.json（稜線 tateyama-skyline.json も作るなら --skip-skyline を外す）
node scripts/make-placeholder-houses.mjs  # 仮の家並み → src/data/iwakuraji-placeholder-houses.json（上の2つのあとに）
```

範囲と原点は `scripts/lib/region.mjs`（原点は前立社壇付近の点のまま、西 -200m・東 +500m・南北 ±200m）。
OSM の建物は空中写真の半分ほどしかないので、道沿いの空き地に名前のない「仮の家」（切妻屋根、1〜2階）を種を固定した乱数で足している。
各棟に `placeholder: true`、件数は `iwakuraji-placeholder-houses.json` の `meta.counts`。下見の結果は [docs/yokai-game/research/2026-10-17-iwakuraji-data-survey.md](../../docs/yokai-game/research/2026-10-17-iwakuraji-data-survey.md)。

## 出会いと会話（段階2）

気配（墨のにじみ）→ 耳を澄ます（6m 以内でボタンか Space を長押し、またはその場で約2秒止まる）→ 夢の姿（白描の板絵）→ 台本の会話 → 伝承の札 → 曼荼羅のピース（白描）→ 縁（顔見知り）。

| 置き場所 | 中身 |
|---|---|
| `src/core/story/` | 描画に依存しない仕組み（現の旅でも使う）。`dialogue.ts` 台本を進める・点検する、`progress.ts` 進み具合の保存（版2。縁は夢では「なじみ」まで、台本で入るピースは夢では白描・現地では彩色まで、金は稽古で。「現地で得たか」の印つき。持ち物・会話の回数・フラグを書いた時も持つ）、`transfer.ts` 引き継ぎコード（書き出し・読み込み・2台の保存を合わせる）、`listen.ts` 耳を澄ます／立ち止まるの判定、`types.ts` データの形 |
| `src/data/scripts/*.json` | 台本（台詞はすべて【創作】。監修前の下書き）。光蔵坊 `kozobo`、ガメ `game`、カーラボーズ `karabozu`、ミノモシ `minomoshi`、調べる地点 `kozobo-shirabe-1`・`-2` と白えびの拾い場所 `shiroebi-spot`（どれもましろだけが話す）、寄り道のガメ `game-yorimichi`（雑談だけ） |
| `src/data/appearance.json`・`clues.json` | 出現の表（場所の種類 × 時間帯。試作は水辺だけ。F-03）と、調べる地点・拾い場所の台本・気配を出す条件・地図に出す呼び名（label）と気配の言葉（kehai）。引き方は `src/core/story/appearance.ts` |
| `src/data/lore-cards.json` | 伝承の札（03 の確認済の内容だけ。出典・確度・03 の番号・監修の状態）。昆布・白えびは伝承ではなく「名産の札」（kind: 名産） |
| `src/data/mandala.json` | 曼荼羅帳の構図（里・麓・山。【創作】）。ピースごとの札と、稽古で並べる札の順（keiko） |
| `src/data/items.json`・`quests.json` | 持ち物（供物・届け物）と悩みごと（帳に出す題、始まり・解けたの見分け方。同時に3つまで） |
| `src/ui/cho.ts` | 帳（三つのページで共通）。曼荼羅帳と縁帳のタブ、稽古（語り返し）で金の縁取り |
| `src/data/yokai.json`・`story-pack.ts` | 妖怪の名前と夢の姿の大きさ、縁帳の紹介（profile・好物 likes・元の伝承 original）、読み込みと点検 |
| `src/yume/encounter/` | 箱庭と画面へのつなぎ（夢の姿・霞・会話の枠・札・曼荼羅帳・音） |

進み具合は `localStorage` の `yume.story.iwakuraji.v2`（見た目などの設定は `yume.v1`）。帳の「最初からやり直す」で消える。保存の名前は `src/core/storage-keys.ts` にまとめている。ほかのタブで保存が変わると、開いているページもそれに合わせる（`ProgressStore.follow`。古いタブが新しい保存を上書きしないように）。入れ替えたら（`ProgressStore.onReplace`）、開いている帳は同じ頁で描き直し（曼荼羅帳・縁帳。会っていない妖怪の頁は一覧に戻す。稽古の間は、稽古はそのままで、後ろの曼荼羅帳だけを描き直す）、現の旅・白描の絵地図は地点の出方と名前を見直す（会話の間は、会話が終わってから）。夢の旅の箱庭は、進み具合が変わるたびに地点の印を合わせている。
「進み具合がある」は、会った妖怪・開いた札・ピース・持ち物・旅印のどれかがあること（`hasProgress`）。フラグだけの保存（「新」の印を見た、など）は数えない（前の名前から写す・引き継ぎコードに入れる・保存を残すお願い）。
**保存の名前を変えた（10/18）**: 公開中の版（`/`）と試しの版（`/preview/`）は同じオリジンで保存も共通なので、前の版のページを開くと、読めない版2 の保存を空として上書きしてしまう。そこで前の版が読まない名前（`yume.story.iwakuraji.v2`・`yume.story.test.v2`・`yume.story.sim.v2`・`yume.testland.v2`）に置き、前の名前（`yume.story.v1`・`yume.story.test.v1`・`yume.testland.v1`）の保存は、いまの名前に保存が無いときだけ写す。前の名前の保存は書き換えず、ふだんは消さない（前の版の保存で、控えにもなる）。ただ、`?cleartest` でテスト用の土地を消すときは、`yume.testland.v1` にある版4 の土地も消す（残すと写し直すため。版3 までの土地は残す）。進み具合の保存（`yume.story.iwakuraji.v2`・`yume.story.test.v2`）だけは、写したあと（進み具合の無い保存は写さずに印だけ）と、やり直したあとに `<名前>.legacy-done` の印を残し、もう写さない。テスト用の土地には印が無い。
保存は版2（10/18）。前の版の保存は読み込むときに版2へ移し、読めない保存（壊れた JSON・形の違う値・新しい版）は `<名前>.broken` に写して残す（消さない）。引き継ぎコードは物語の進み具合（立山のふもと・テスト用の土地のうち、進み具合のある土地。コードの中では保存の名前ではなく土地の名前で持つ。版2。前の形のコードも読める）だけを運び、テスト用の土地（位置）・シミュレーター・端末の設定は運ばない。読めないコードは「新しい版で作った」「中身が読めない」「形が読めない」を分けて断り、端末には何も書かない。`yume.persist.v1` は、端末に保存を残すお願い（`navigator.storage.persist()`）をしたかの印。お願いは、進み具合があるときに、ページを開いただけではせず、旅のページで遊び始めてからのタップのあと（リンクと、ページを読み込み直すボタン `data-leaves` の押しは数えない）、引き継ぎを読み込んだあと、入口で三つの約束の札を出したとき（`src/entrance/main.ts`。旅へ移るボタンの押しでは頼まない）に一度だけする（`src/ui/persist.ts`）。

## 悩みと小さな遊び（段階3b）

- **とりもつ**（悩み #1。ガメ⇄カーラボーズ）: 伝言を運び、伝え方を選ぶ。家でも現地でも始めて解ける。
- **払わずに待つ**（ミノモシ番外）: 体につく光（光として描くのは【創作】）。払うと増え、待つと離れる（`ui.ts` の MatsuGame）。
- **調べる→鎮め**（悩み #2。光蔵坊「人はわしの話をどう語っておる」）: 2回目に会うと頼まれ、道の調べる地点（夢の旅では箱庭の同じ地点、現の旅では立ち止まる）で札①②を拾う。戻ると絵解き鎮め（`ui.ts` の EtokiGame）で話の順に並べる。点数・打ち切りはなく、違えると墨の渦が少し濃くなるだけ。拾っていない札と、まだ作っていない札③（刀尾権現。PO・監修の確認待ち）は白紙で出て、ましろが中身を言わずに先へ進める。並べ終えると「なじみ」。
- **寄り道**（出現の表の水辺）: 川・用水沿いの道の地点で、昼・会ったあとのガメが雑談で出る（悩みは始めない・縁も上げない）。逢魔が時のくらがりは段階4なので、いまは気配だけ。夜は気配だけ。岩峅寺には条件に合う水辺の道が無いので、テスト用の土地でだけ出る。

## 帳と届ける悩み（段階4a）

- **帳**（三つのページの「帳」ボタン）: 曼荼羅帳と縁帳。縁帳は、会った妖怪ごとに、縁の糸（気配＝糸くず、顔見知り＝一本の糸、なじみ＝より糸、語り仲間＝組紐、えにし＝結び目。数字は出さず、形と文字で）、会話の回数による糸の艶、夢・現地で会った印、人となり（【創作】）、好物（渡したあとに分かる）、悩み（抱えている・解けた）、伝承の札（出典つき）を見せる。上に持ち物。
- **稽古と金の縁取り**: 現地で色が入ったピースを開き「稽古する（語り返す）」で、札を話の順に並べる（絵解き鎮めの、渦の無い形）。並べ終えると金の縁取り（家でも現地でも）。札が2枚以上あるピースだけ（光蔵坊・ミノモシ）。
- **届ける**: 悩み #10（とりもつのお返しにカーラボーズからもらう昆布を、光蔵坊へ）と #11（ガメに頼まれて、白えびを受け取る地点 `iwakuraji-c3` で受け取り、ガメへ）。渡すと名産の札（昆布の道・富山湾の宝石）が開き、「なじみ」になる。同時に抱える悩みは3つまで（4つ目はましろが「また今度にしよう」）。
- **引き継ぎ（試作）**: 入口の「引き継ぎ（試作）」で、引き継ぎコードを作る・読み込む。サーバーはまだ使わない（置き場所・保存期間は PO の確認待ち）。読み込むと、いまの端末の保存と合わせる（縁やピースは下がらない）。

## 現の旅（段階3）

はじめ（土地を選ぶ）→ 三つの約束（初回だけ。F-60。入口で読んでいれば出さない）→ 位置の許可の説明 → 素の地図（D1）。
歩く → 気配（300m 以内。150m で鈴）→ 地点の 40m 以内で立ち止まる（止まりの判定は段階0.5 と同じ。または「足を止めた」ボタン）→ 3秒で澄む →
色のついた姿（AR 段階0。「カメラで見る」で AR 段階1）→ 台本の会話（夢で会っていれば再会）→ 札・彩色 → 節を終えたら旅印（D4）。

| 置き場所 | 中身 |
|---|---|
| `src/core/utsutsu/` | 描画に依存しない決まり。`engine.ts`（状態・気配・澄む・出会い）、`zones.ts`（お休みの範囲の出入り）、`transit.ts`（道中）、`sun.ts`（日の出・日の入り、逢魔が時・夜） |
| `src/core/location/` | 位置の型・Fix の作り方・立ち止まりの判定（段階0.5 の GPS の検証と共通） |
| `src/utsutsu/` | 画面。`map-view.ts`（Canvas 2D の素の地図。外の地図タイルは使わない）、`location.ts`（GPS と位置シミュレーター）、`encounter.ts`（AR 段階0・1）、`test-land.ts`（テスト用の土地）、`main.ts` |
| `src/data/sections.json` | 節と旅印（いまは「麓 一の節」＝光蔵坊に現地で会って色を入れたら終わり） |
| `src/yume/encounter/stamp.ts` | 旅印の絵柄（インク1色の藍。御朱印に似せない） |

- **止めるとき**: 道中（時速約11km 以上が続く）、お休みの範囲（境内・墓地。縁から 10m）、逢魔が時（日の入りの30分前〜20分後）、夜。気配の表示は、道中とお休み以外では続ける。
- **保存**: 立山のふもとは夢の旅と同じ `yume.story.iwakuraji.v2`（再会できる）。テスト用の土地は `yume.story.test.v2`（家の白描の絵地図と共通。土地を作ったとき、まだ空なら夢の旅の保存を写す）。シミュレーターは `yume.story.sim.v2`（始めるたびに、立山のふもとなら `yume.story.iwakuraji.v2`、テスト用の土地なら `yume.story.test.v2` を写すので、もとの保存は変わらない）。位置は保存しない。
- **テスト用の土地**（F-07。版4）: いまいる所のまわり約 800m 四方の OSM データを OSM API から読み、社寺・墓地をお休みの範囲にし、公道の上に、決まった妖怪の地点を4つまで（光蔵坊はいちばん近く。ガメとカーラボーズは、2体そろって置けるときだけ）、調べる地点を2つ、水辺の道の地点を2つまで、白えびを受け取る地点を1つ（悩み #11。調べる地点と同じ決まりで、ガメがいるときだけ）置く。前の版の土地は使えないので作り直す。**この端末の localStorage（`yume.testland.v2`）にだけ残し、リポジトリには入れない**（テストする人の家の近くの位置なので）。`?cleartest` で消す。
- **位置シミュレーター**（F-06。`?sim`）: 地図をタップして歩く・瞬間移動、速さ（歩く・走る・乗り物）、精度、時刻（昼・暗くなる前・逢魔が時・夜）、地点まで歩く、端末の速さなし、止まると更新を休む。
- 位置は https のページでしか使えない（GitHub Pages、または開発サーバーを https で）。Claude のアーティファクトでは位置もカメラも使えない。

## 白描の絵地図（段階3b。テスト用の土地の家の側）

`ezu.html`。現地で作ったテスト用の土地を、和紙に墨の線の 2D の絵地図で見せる（02 F-07「家の側は、地元パックでは白描の2D だけ」、04 §3.8 の提案）。
名所に指を置いて約2秒そのままにすると、白描の夢の姿が浮かぶ（名所をタップして「耳を澄ます」の長押し、キーボードは Tab で選んで Space でもよい）。
進み具合は現地のテスト用の土地と同じ `yume.story.test.v2` なので、ここで会った妖怪とは現地で「再会」になる。時間（昼・夕・夜）は「時間」で切り替え（`yume.ezu.v1`）、夜は気配だけ。
土地が無い端末では、現地で作る方法を案内する。位置は使わず、土地をどこにも送らない。

三角形と描画命令の数は、見ている範囲で変わる。下は **はじめの位置**（PC 1280×800・解像度 ×1・ズーム 62m・東向き。位置 (245.7, 19.3)）で計った値（10/17）。

## データの出典と義務

- 道・川・建物などは © OpenStreetMap contributors（ODbL 1.0）。箱庭用に加工したデータ（`src/data/iwakuraji-osm.json`）は ODbL で提供する。加工の手順は `scripts/` に公開している。画面には出典を常に表示する。
- 標高は国土地理院の標高タイル（基盤地図情報数値標高モデル）を加工して作成。画面に出典を表示する。
- 社寺の名前や由緒は、了承を得るまでデータにも画面にも入れない（`fetch-osm.mjs` で名前を落としている）。境内は「お休みの範囲」として、中には入れない。

- 伝承の札は、遊ぶ人には題・本文・出典だけを見せる。確度・調べ・監修の状態は、URL に `?debug` を付けたときだけ出る（開発と監修の確認用）。
