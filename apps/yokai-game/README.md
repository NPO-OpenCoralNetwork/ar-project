## 動かす

```sh
npm ci
npm run dev            # 開発サーバー（--host 付き。同じ LAN のスマホから開ける）
npm run build          # 型チェック＋ dist/ へビルド（GitHub Pages に公開されるもの）
npm run typecheck      # 型チェックだけ
npm run test:story     # 物語の仕組みのテスト（tests/*.test.ts。東京とニューヨークの二つの時間帯で走らせる）
npm run check:story    # 物語のデータの点検（問題が1つでもあれば失敗。build には入れていない）
npm run build:artifact # 夢の旅（yume.html）だけを1つの HTML（dist-artifact/index.html）にまとめる
```

公開: `.github/workflows/yokai-pages.yml` が GitHub Pages に出す（リポジトリの Settings → Pages → Source が「GitHub Actions」のときだけ。まだなら、ビルドの確認だけで終える）。

| URL | 中身 |
|---|---|
| `https://npo-opencoralnetwork.github.io/ar-project/` | 本番（main）の入口。夢の旅は `yume.html`、現の旅は `utsutsu.html` |
| `https://npo-opencoralnetwork.github.io/ar-project/preview/` | 確認用。いちばん新しく更新された `claude/**` ブランチ（どのコミットかは `preview/version.txt`）。夢の旅は `preview/yume.html`、現の旅は `preview/utsutsu.html` |

- Pages のサイトはリポジトリに1つだけなので、公開は必ず main の上で行い、main と確認用のブランチを1つにまとめて出す。`claude/**` へのプッシュは、ビルドを確かめてから main の上の公開を呼び出す。
- 本番と確認用は同じオリジン（`npo-opencoralnetwork.github.io`）なので、`localStorage` の保存（進み具合・テスト用の土地）と、位置・カメラの許可は両方で共通になる。
- HTML は最大10分ほどキャッシュされることがある。新しくならないときは読み込み直す。

## データを作り直す

```sh
node scripts/fetch-osm.mjs   # OpenStreetMap → src/data/iwakuraji-osm.json（--offline で手元の生データから）
node scripts/fetch-dem.mjs --skip-skyline  # 地理院の標高タイル → src/data/iwakuraji-dem.json（稜線 tateyama-skyline.json も作るなら --skip-skyline を外す）
node scripts/make-placeholder-houses.mjs  # 仮の家並み → src/data/iwakuraji-placeholder-houses.json（上の2つのあとに）
```

範囲と原点は `scripts/lib/region.mjs`（原点は前立社壇付近の点のまま、西 -200m・東 +500m・南北 ±200m）。
OSM の建物は空中写真の半分ほどしかないので、道沿いの空き地に名前のない「仮の家」（切妻屋根、1〜2階）を種を固定した乱数で足している。
各棟に `placeholder: true`、件数は `iwakuraji-placeholder-houses.json` の `meta.counts`。下見の結果は [docs/yokai-game/research/2026-10-17-iwakuraji-data-survey.md](../../docs/yokai-game/research/2026-10-17-iwakuraji-data-survey.md)。

## 出会いと会話（段階2）

気配（墨のにじみ）→ 耳を澄ます（6m 以内でボタンか Space を長押し、またはその場で約2秒止まる）→ 夢の姿（白描の板絵）→ 台本の会話 → 伝承の札 → 曼荼羅のピース（白描）→ 縁（顔見知り）。

進み具合は `localStorage` の `yume.story.iwakuraji.v3`（見た目などの設定は `yume.v1`。ましろの覚え書き（呼び名）は端末に1つの `yume.memo.v1`）。帳の「最初からやり直す」で消える（覚え書きは消えない）。保存の名前は `src/core/storage-keys.ts` にまとめている。ほかのタブで保存が変わると、開いているページもそれに合わせる（`ProgressStore.follow`。古いタブが新しい保存を上書きしないように）。入れ替えたら（`ProgressStore.onReplace`）、開いている帳は同じ頁で描き直し（曼荼羅帳・縁帳。会っていない妖怪の頁は一覧に戻す。稽古の間は、稽古はそのままで、後ろの曼荼羅帳だけを描き直す）、現の旅・白描の絵地図は地点の出方と名前を見直す（会話の間は、会話が終わってから）。夢の旅の箱庭は、進み具合が変わるたびに地点の印を合わせている。
「進み具合がある」は、会った妖怪・開いた札・ピース・持ち物・旅印のどれかがあること（`hasProgress`）。フラグだけの保存（「新」の印を見た、など）は数えない（前の名前から写す・引き継ぎコードに入れる・保存を残すお願い）。
**保存の名前を変えた（10/18）**: 公開中の版（`/`）と試しの版（`/preview/`）は同じオリジンで保存も共通なので、前の版のページを開くと、読めない版2 の保存を空として上書きしてしまう。そこで前の版が読まない名前（`yume.story.iwakuraji.v2`・`yume.story.test.v2`・`yume.story.sim.v2`・`yume.testland.v2`）に置き、前の名前（`yume.story.v1`・`yume.story.test.v1`・`yume.testland.v1`）の保存は、いまの名前に保存が無いときだけ写す。前の名前の保存は書き換えず、ふだんは消さない（前の版の保存で、控えにもなる）。ただ、`?cleartest` でテスト用の土地を消すときは、`yume.testland.v1` にある版4 の土地も消す（残すと写し直すため。版3 までの土地は残す）。進み具合の保存（`yume.story.iwakuraji.v2`・`yume.story.test.v2`）だけは、写したあと（進み具合の無い保存は写さずに印だけ）と、やり直したあとに `<名前>.legacy-done` の印を残し、もう写さない。テスト用の土地には印が無い。
**保存の名前を、もう一度変えた（10/19、段階4b）**: 便り・夜話・絵解きを足した版3 の保存は、4a の版のページが読めずに上書きしてしまうので、上と同じ形で名前を `.v3` にした（`yume.story.iwakuraji.v3`・`yume.story.test.v3`・`yume.story.sim.v3`）。写すのは **v3 ← v2 ← v1** の順（`migrateLegacySave`）: いまの名前に保存も `.legacy-done` の印も無ければ、新しい版の名前から見ていき、保存があればそれだけを見て止め（進み具合のある保存だけを、直した形で写す）、保存が無くてその版の印があれば止める（その版で写してからやり直した。古い版から写し直さない）。どちらも無ければ次の古い版へ。止めたら印を残す。どの版にも保存も印も無ければ何も書かない。前の名前（v2・v1）には書かず、消さない。テスト用の土地そのもの（`yume.testland.v2`）の名前は変えていない。シミュレーターの保存は始めるたびに写すので、前の名前からは移さない。ましろの覚え書き（呼び名）は、土地ごとの保存の外に、端末に1つだけ置く（`yume.memo.v1`。`{ v: 1, yobina: { value, at } }`。消すと value が null の「消した印」を残し、引き継ぎで合わせても戻らない。土地のやり直しでは消えない）。
保存は版3（10/19。版2 は 10/18）。前の版（1・2）の保存は読み込むときに版3へ移し、読めない保存（壊れた JSON・形の違う値・新しい版）は `<名前>.broken` に写して残す（消さない）。引き継ぎコードは物語の進み具合（立山のふもと・テスト用の土地のうち、進み具合のある土地。コードの中では保存の名前ではなく土地の名前で持つ。版3。版1・版2 のコードも読める）と、ましろの覚え書き（呼び名。書いたか消したかがあるときだけ。読めなければ覚え書きだけ捨てる）だけを運び、テスト用の土地（位置）・シミュレーター・端末の設定は運ばない。読めないコードは「新しい版で作った」「中身が読めない」「形が読めない」を分けて断り、端末には何も書かない。`yume.persist.v1` は、端末に保存を残すお願い（`navigator.storage.persist()`）をしたかの印。お願いは、進み具合があるときに、ページを開いただけではせず、旅のページで遊び始めてからのタップのあと（リンクと、ページを読み込み直すボタン `data-leaves` の押しは数えない）、引き継ぎを読み込んだあと、入口で三つの約束の札を出したとき（`src/entrance/main.ts`。旅へ移るボタンの押しでは頼まない）に一度だけする（`src/ui/persist.ts`）。

## 悩みと小さな遊び（段階3b）

- **とりもつ**（悩み #1。ガメ⇄カーラボーズ）: 伝言を運び、伝え方を選ぶ。家でも現地でも始めて解ける。
- **払わずに待つ**（ミノモシ番外）: 体につく光（光として描くのは【創作】）。払うと増え、待つと離れる（`ui.ts` の MatsuGame）。
- **調べる→鎮め**（悩み #2。光蔵坊「人はわしの話をどう語っておる」）: 2回目に会うと頼まれ、道の調べる地点（夢の旅では箱庭の同じ地点、現の旅では立ち止まる）で札①②を拾う。戻ると絵解き鎮め（`ui.ts` の EtokiGame）で話の順に並べる。点数・打ち切りはなく、違えると墨の渦が少し濃くなるだけ。拾っていない札と、まだ作っていない札③（刀尾権現。PO・監修の確認待ち）は白紙で出て、ましろが中身を言わずに先へ進める。並べ終えると「なじみ」。
- **寄り道**（出現の表の水辺）: 川・用水沿いの道の地点で、昼・会ったあとのガメが雑談で出る（悩みは始めない・縁も上げない）。水辺の逢魔が時は気配だけ（くらがりは段階4b で、帳の影＝便りの画面から出る）。夜は気配だけ。岩峅寺には条件に合う水辺の道が無いので、テスト用の土地でだけ出る。

## 帳と届ける悩み（段階4a）

- **帳**（三つのページの「帳」ボタン）: 曼荼羅帳と縁帳。縁帳は、会った妖怪ごとに、縁の糸（気配＝糸くず、顔見知り＝一本の糸、なじみ＝より糸、語り仲間＝組紐、えにし＝結び目。数字は出さず、形と文字で）、会話の回数による糸の艶、夢・現地で会った印、人となり（【創作】）、好物（渡したあとに分かる）、悩み（抱えている・解けた）、伝承の札（出典つき）を見せる。上に持ち物。
- **稽古と金の縁取り**: 現地で色が入ったピースを開き「稽古する（語り返す）」で、札を話の順に並べる（絵解き鎮めの、渦の無い形）。並べ終えると金の縁取り（家でも現地でも）。札が2枚以上あるピースだけ（光蔵坊・ミノモシ）。
- **届ける**: 悩み #10（とりもつのお返しにカーラボーズからもらう昆布を、光蔵坊へ）と #11（ガメに頼まれて、白えびを受け取る地点 `iwakuraji-c3` で受け取り、ガメへ）。渡すと名産の札（昆布の道・富山湾の宝石）が開き、「なじみ」になる。同時に抱える悩みは3つまで（4つ目はましろが「また今度にしよう」）。
- **引き継ぎ（試作）**: 入口の「引き継ぎ（試作）」で、引き継ぎコードを作る・読み込む。サーバーはまだ使わない（置き場所・保存期間は PO の確認待ち）。読み込むと、いまの端末の保存と合わせる（縁やピースは下がらない）。段階4b のコード（版3）は、便り・夜話・絵解きの記録と、ましろの覚え書き（呼び名）も運ぶ（覚え書きは項目ごとに新しいほう。消した印も戻らない）。4a の版は版3 のコードを「新しい版」として断る。

## 立山の時刻と便り（段階4b）

- **立山の時刻**（`src/core/story/clock.ts`）: 家のページ（夢の旅・白描の絵地図・入口の便り）は、どの土地で遊んでも、立山のふもとの原点（`STORY_ORIGIN`＝`iwakurajiPack.origin`）の日の出・日の入りで動く1つの時計を使う。テスト用の土地の位置は時計にも使わない（F-52）。日本時間はミリ秒に9時間を足して出し、端末のローカル時刻の読み方（`getHours` など）は使わない。物語の日は 04:00〜翌04:00（鍵は `YYYY-MM-DD`）。昼＝日の出〜逢魔が時、逢魔が時＝日の入りの30分前〜20分後（`sun.ts` と同じ）、夜＝それ以外（04:00〜日の出も夜）。夜話は日の入り20分後〜翌04:00。その日の太陽は、いつもその日の 12:00 から求める。現の旅の出会いの決まり（逢魔が時・夜に止める）は、これまでどおり、その土地の太陽で見る。
- **箱庭と絵地図の時間**（`src/ui/home-time.ts`・`src/ui/offer.ts`）: はじめての回だけ昼、2回目から「いま」（立山の時刻）。「時間」（箱庭は T キーも）で いま → 昼 → 夕 → 夜 → いま と回し、手で選んだのはそのページの間だけ（保存の time は書くが、もう読まない）。いまのときは1分ごとと、ページに戻ったときに見直し、会話・帳・札の間は待つ。立山の時刻が逢魔が時に入ると、日に一度、お知らせ「逢魔が時。帳のすみに、影がさした。」と風の音（`Sound.wind()`。合成の仮の音）。いまの夜に入ると、ページごとに一度だけ、ましろの申し出（［昼の夢にする］、夜話が来ていれば［帳の「便り」をひらく］）。会話のあとで今夜だれかが来るようになったら、その夜に一度だけ「帳の「便り」に、だれか来ている。」。見た目の時間帯は見た目だけで、夜話・くらがり・時間のピースは、いつも立山の時刻で決まる（手で夕にしても、くらがりは来ない）。
- **便りの画面**（`src/ui/tayori.ts`。DOM だけで、three.js は読まない）: 帳の3つ目のタブ「便り」（夢の旅は立山のふもと、白描の絵地図はテスト用の土地、現の旅はいまの土地の保存）と、入口の `index.html#tayori`（立山のふもとの保存。画面と物語のデータは、入口のはじめの絵が出たあとに `import()` で読む）。上から、ましろの一言（時間帯で変わる）、逢魔が時（帳の影＝くらがり。［話を聞く］で夕暮れの和紙の会話）、今夜の夜話、きょうの絵解き（［つくる］［見る］と、これまでの絵解き14日分）、届いた便り（たたんだ和紙。押すとその場でひらく）。描くとき・1分ごと・ページに戻ったとき・会話のあとに、届く便りを届ける（`deliverDue`。何度呼んでも同じ）。帳のボタンと入口の「便り」の「新」は字だけで、数は出さない（読んでいない便りがある、家で夜話が来ている、家で逢魔が時に今日まだくらがりと話していない）。入口のましろのあいさつも、逢魔が時 → 夜話が来ている → 夜 → 読んでいない便り → ふだん の順で変わる。
- **現の旅の帳の便り**（現地の側＝site）: 便りと今日の絵解きだけ。夜話とくらがりは始めず、夜には「夜話は、宿や家で。入口の「便り」から聞けます。」（夜話は土地ごとなので、テスト用の土地では「夜話は、家で。白描の絵地図の「帳」の「便り」から聞けます。」。入口の便りは立山のふもとの保存だけ）、立山の逢魔が時には「くらがりとは、家に着いてから話そう。」（まだ会っていなければ名前を出さず「帳のすみの影とは、…」）とだけ出す（ボタンは無い）。「今日はここまで」は右上に、止まっているときだけ出す（道中・歩いている間は出さない。F-61）。旅印を押したあとの札にも［今日の絵解きをつくる］。
- **夜話**（`src/core/story/yobanashi.ts`）: その日に会った「なじみ」以上で、夜話の台本（`yokai.json` の yobanashi）のある妖怪から、一晩に一人（夜話をいちばん長く聞いていない妖怪。場面は聞いていないものから上の順で、聞き終えたら again）。ほかはボタンの無い気配の一行（`tayori.json` の nightKehai）。始めた時に記録し（保存の nights）、途中で閉じたら同じ妖怪・同じ場面で「つづきを聞く」。会話の回数（糸の艶）だけを1つ増やし、会ったこと・縁は変えない。「会った」は、会話で妖怪が最初に話した時（lastMet。途中で閉じても残る）。
- **便り（手紙）**（`src/core/story/letters.ts`・`src/data/tayori.json`）: 決まった便り（フラグが立った物語の日から days 日あと。また聞き「川の話」は悩み #1 の翌日、「山を見る天狗」は #2 の翌日、#9 の「影のこと」はすぐ。また聞きは1日に1通）と、「ましろの便り」（`fumi:<日>`。遊んだ日のあと、はじめて開いた日に1通。その日にほかの便りが届いていれば出さない）。「遊んだ」は保存にもうある時刻から見る（便りを読んだ・夜話を聞いたは数えない）。届いた時に選んだ部品の id を残し（保存の letters）、文は読む時に組み立てる。
- **くらがりと悩み #9**（`src/data/scripts/kuragari.json`、絵は `src/yume/encounter/arts/kuragari.ts`）: 立山の逢魔が時に、便りの画面の「逢魔が時」から話す（箱庭・現地には出ない）。どの入口も時間のピース `fumoto-kuragari` を通る（会話を始めた時が逢魔が時なら、家でも彩色。効果 `timePiece`）。はじめての夕暮れに問いを受け（`kg-q9-asked`）、ましろの便り「影のこと」を読み（`kg-mashiro-read`）、べつの日の夕暮れに伝え方を3つから選ぶと「なじみ」と札 `mandala-2`（`kg-q9-done`）。金の縁取りは稽古で（札 `mandala-1`・`mandala-2`）。
- **ましろの覚え書き**（`src/core/story/memo.ts`・`src/ui/memo-sheet.ts`）: 呼び名だけ。最初のましろの便りの［呼び名を教える］と、縁帳の「ましろの覚え書き」の行（書く・書きなおす・消す）。NFKC にそろえて1〜8字、ひらがな・カタカナ・漢字・A–Z/a–z・ー・・・々 だけ（書かない名前も断る）。使うのはましろだけ（ましろの台詞と便りの `{呼び名}`。無ければ「きみ」。妖怪の台詞と選択肢では点検で止める）。遊ぶ人の字なので、画面には `textContent` か `escapeHtml` でだけ出す。

**テスト用の時計**（`src/core/debug-clock.ts`。04 §3.9）:
- `?debug` のときだけ効く。`?debug&clock=2027-01-16T16:40`（日本時間）でその時刻に、`clock=+90m`・`clock=-2h`・`clock=+1d` で実時刻から前後へ、`clock=off` で実時刻へ。合わせた差は、そのタブの `sessionStorage`（`yume.debug.clock.v1`）に残り、時計はそこから進み続ける。同じタブで別のページへ移っても続く（入口は、いまの差を相対の `clock=+…m` で旅のページへ渡す。分に切り上げるので、次のページで時刻が巻き戻らない）。便りの時計のボタンで合わせ直すと、ページの URL の `clock` も書き換える（読み込み直しても、合わせた時刻のまま。「いま」では消す）。`?debug` の無いページは、差が残っていても実時刻。
- 時計を動かしている間は、左下に「時計: 1月16日 16:40（テスト）」（現の旅は判定の中身の欄）。`?debug` の便りの画面には、時計を動かすボタン（いま・昼 12:00・逢魔が時（日の入りの10分前）・夜 20:00・次の朝 08:00・+1日）と、時計・夜話・便りの様子が出る。
- **注意: 進み具合と覚え書きの時刻（会った時・便りの届いた時・夜話・絵解き・フラグの時刻）も、この時計で保存に書く。** 実際の時刻に戻しても先の日付の記録が残り、便りが届かなくなるなどの狂いが出るので、**試すときは使い捨てのブラウザのプロフィール（シークレットウィンドウなど）で**。ふだん遊ぶ保存や、テスターの端末では使わない。
- 現の旅の出会いの決まり（逢魔が時・夜）は、この時計では動かない（位置シミュレーターの時刻で試す）。

**テストと点検**:
