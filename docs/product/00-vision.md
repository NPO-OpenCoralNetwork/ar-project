## 0. この文書が答えること

10/17 の PO の発言の要旨:

> 今作ってくれたものはとてもいい。ただ、もともとこのプロジェクトは AR 事業として、それぞれの街に AR のメタバースを作り、スポンサーが入ってくるイメージだった。プロジェクト自体の認識がずれているかもしれない。あなたが作ったテイスト（光と霞）はいいので、以前のサイトのテイストも変えた方がいい。別にもう一度作り直して、どんなサイト・アプリの仕様・UI/UX にするべきか考えてほしい。**普通にゲームとして**やりたい。でも、**サーバーがあっていろいろな街に入れる**、というのはいいと思っている。その上でどうするか。

この文書の答えは次の3行です。

1. **プレイヤーにとっては「普通のゲーム」1本。** 街は、そのゲームの中で「入れる土地」として一つずつ増えていく。
2. **もともとの構想（街ごとのワールド・サーバー・スポンサー・作り手・自治体）は、捨てずに「裏方」に置く。** プレイヤーには見せず、パートナーには「AR City Vision」の名前で見せる。**AR と作り手の場は残すが、主役にはしない**（AR は現の旅の演出、作り手の場は2年目以降。どちらも PO の確認が要る。§10 #1b・#1c）。
3. **スポンサーはゲームの体験を壊さない形でだけ入れる。** 世界の中の「休み処」と、遊び終わりの「お礼の札」にだけ出る。広告は出さない。

### 0.1 この文書の言葉（作った言葉の短い説明）

| 言葉 | 意味 |
|---|---|
| 土地・巻 | ゲームの中で入れる街。一つの土地を「巻」として一つずつ足す（例: 立山の巻） |
| 箱庭 | 家から入って歩ける、その土地の数百m四方の3Dの舞台 |
| 夢の旅／現の旅 | 家で箱庭を歩く遊び／現地で本当の道を歩く遊び。同じ妖怪・同じ物語 |
| 灯り | ほかの旅人がその地点に残した光。誰のものかは分からない。サーバーがあることを感じる仕掛け |
| 休み処 | 現地のお店が、旅人の寄り道先になる仕組み。箱庭では縁台と行灯の形で、看板は出さない |
| 協力先・協賛 | 休み処になってくれるお店／祭りを支えてくれるお店・企業 |
| お礼の札 | 祭りや巻の終わりに流れるクレジット。協賛の名前が出る数少ない場所 |
| 土地ひらき・協定先 | 自治体・観光協会と一緒に新しい土地をひらく取り組み／その相手 |
| 範囲の層 | 「ここには何を置いてよいか」を地図の範囲ごとに決めた層。境内などは「お休みの範囲」で、何も置かない |
| 門の審査 | 土地を開ける前に、開ける条件（§5.3）がそろっているかを確かめること |
| 器 | 土地を増やすための仕組み（データの形・サーバー・制作キット）。プレイヤーには見せない |
| 出し物 | 作り手が出す、伝承に触れない作品（光の作品・飾り・音など）。2年目以降 |
| 作る段階・AR 段階 | 「作る段階0〜6」は作る順番（05 §6）。「AR 段階0〜3」は AR の見せ方（[01 技術の選定](../yokai-game/01-tech-stack-decision.md)）。段階0＝カメラなし、段階1＝カメラの映像に重ねる |

## 1. ひとことで

**妖怪と仲良くなりながら、日本のいろいろな土地を旅するゲーム。**
家では土地の3Dの箱庭に入って歩き（夢の旅）、行ける人は現地で同じ妖怪に再会する（現の旅）。土地は「巻」として一つずつ増えていく。サーバーがあることは、「ほかの旅人の灯りが見える」「新しい土地の噂が届く」という形でだけ感じる。

最初の巻は立山（麓の岩峅寺・芦峅寺）。いまの three.js の試作（夢の旅の箱庭、GPS の検証ページ）と、05 の作る順番（段階0〜6、3月の麓での現地テスト）は、そのまま続ける。

## 2. もともとの構想（README）との関係

README の AR City Vision は「街ごとに AR の空間を作り、作り手・一般の人・企業・自治体・教育機関・NPO が参加し、手数料と協賛で回り、収益の一部を地域に返す」構想です。中身はほとんど引き継ぎます。変えるのは**見せ方と順番**です。

| README の要素 | このプロダクトでの形 | 変えたこと・理由 |
|---|---|---|
| 街ごとの AR のワールド | **土地（巻）**。一つの土地＝家から入る3Dの箱庭（夢の旅）＋現地の同じ場所の地図と AR（現の旅）＋その二つにまたがって残るほかの人の灯り | 「メタバース」とは呼ばない。街全体の複製ではなく、数百m四方の物語の舞台にする（05 §4.1。人のいない3D空間で終わった自治体の例を避ける） |
| 中央のサーバー | 土地の一覧と地域パックを配る／引き継ぎのセーブデータ／灯りの数を持つ。のちに、決まった夜だけ少人数が集まる部屋 | 常に何百人も同時に入る大きなサーバーから始めない。位置の履歴は残さない（02 F-52） |
| 一般ユーザー | **プレイヤー** | 「参加者の一人」ではなく、いちばん大事な相手として最初に置く |
| 作り手（アーティスト） | 運営が依頼して絵・3D・音を作る人。のちに、伝承に触れない「出し物」を招待制で出せる | 誰でも作って売れる場所からは始めない。伝承と宗教のルール（04 §5、05 §3.2）とぶつかるため |
| 企業スポンサー | 現地の**休み処**（寄り道先）、ゲームの中の祭りの**協賛**、実物のおみやげの共同企画 | 画面の広告・PR 空間・看板は売らない |
| 自治体 | **土地ひらき（仮）**の協定先。地元の窓口、現実の物（案内板・駅など）を地点にする、巻の制作の委託 | 変えない。1年目の売上のいちばんの目標にする |
| 教育機関 | 当面は関わらない（教材にしない。00 §1「学びはご褒美として後から付いてくる」）。のちに、大学などで制作キットを使う授業を案として持つ | 優先度を下げた |
| NPO・社会起業家 | 当面は関わらない。外向けに「非営利」「NPO」と書かない（08 §0.3） | 法人の形が決まっていないため |
| 収益の20%を社会貢献基金へ、投票で使い道 | **当面は外す。条件つきで後に残す**（§6.4） | 法人の形が未定。寄付先に社寺や宗教行事が入ると、ゲームが宗教にお金を流す形になる |
| 6本の収益の柱 | §7.4 の表で、一つずつ「いまやる／条件つきで後に残す／やらない」を決めた | 順番を「遊ぶ人が集まる → 協賛の価値が出る」にした |
| README の見た目（英語、絵文字、仮のロゴ、バッジ） | やめる。サイトとアプリは 06「光と霞」に合わせる（[02](02-site.md)） | README は開発者向けの説明に書き直し、構想はこの文書に移す（§10 #6）。**PO の以前のサイトはまだ見ていない**（リポジトリの中にない）。URL をいただければ、残す要素と変える要素を書き出す（§10 #8） |

**AR について**: AR は、現の旅の出会いの場面で、カメラの映像に妖怪を重ねる（AR 段階1）。カメラを使わない形（AR 段階0。和紙の背景に妖怪が出る）も選べる（04 §0、02 F-10・F-11）。「AR 段階」は AR の見せ方の段で、作る段階0〜6とは別のもの。主役は3Dの箱庭と物語です（AR を看板にしないことは PO の確認が要る。§10 #1b）。パートナー向けの説明でも、何が AR で何が3Dかを分けて書き、言葉で期待を上げすぎないようにします。

## 3. ブランドの構成

### 3.1 二段にする

| 段 | 誰に見せるか | 名前 | どこに出すか |
|---|---|---|---|
| ゲームの名前 | プレイヤー | ゲームのタイトル1つ（§3.2 から選ぶ） | アプリ、サイトのプレイヤー向けのページ、パートナー向けの資料の最初 |
| 土地の巻の名前 | プレイヤー | 「立山の巻 ― 白い曼荼羅帳（仮）」のように、巻ごとに題を付ける | 絵地図、土地の入口、帳 |
| 運営の名前 | 自治体・お店・作り手・監修者・報道 | **AR City Vision**（README の名前を、運営プロジェクトの名前として残す） | サイトのフッター、「運営について」、パートナー向けのページ、アプリの支度＞クレジットの1行 |
| 協力の仕組みの名前 | 同上 | **土地ひらき（仮）**（自治体と土地を開く協定）、**休み処（仮）**（お店の寄り道先） | パートナー向けのページ、ゲームの中では休み処だけが出る |

**言葉の決まり**
- 「メタバース」「プラットフォーム」は、プレイヤー向けにもパートナー向けにも使わない。呼び方は「土地」「巻」「箱庭」。
- 「白い曼荼羅帳」は**立山の巻の題にとどめる**。曼荼羅は立山の信仰に根ざした言葉なので、ほかの土地まで含むゲーム全体の名前にはしない。
- パートナー向けの資料は、必ずゲームの画面とゲームの名前から始める（「このゲームの中に、あなたの土地ができます」）。器（仕組み）から説明しない。

### 3.2 ゲームの名前の案（仮。商標・同名の作品は**まだ調べていない**）

| 案 | 名前 | よい点 | 気になる点 |
|---|---|---|---|
| A | **ゆめうつつ** | 二つの旅（夢の旅・現の旅）がそのまま名前になる。「光と霞」の霞んだ見た目と合う。短い | 一般的な言葉で、検索で埋もれやすい（副題で補う: 「ゆめうつつ ― 妖怪と土地の旅」など） |
| B | **えにし旅帳** | 縁（えにし）はゲームの核の仕組みそのもの。「巻を足す」形が分かりやすい | 「帳」が御朱印帳に寄って見えないか、見た目で注意が要る |
| C | **灯（ともしび）の土地** | ほかの旅人の灯りと、06 の夜の見た目に直結する | 妖怪・伝承のゲームだと名前から伝わりにくい |

**おすすめ: A「ゆめうつつ」**。二つの旅という、このゲームにしかない形を名前で約束できるため。決める前に商標と同名の作品を調べる。

**04 の仮タイトル案との関係**: 04 §1・§7 は仮タイトルの推しを「立山えとき道中」としている。これは立山だけの名前で、土地が増えると合わないので、ゲーム全体の名前とは分ける。「立山えとき道中」は、立山の巻の題か副題に回せる（例: 「ゆめうつつ ― 立山えとき道中」。巻の題「白い曼荼羅帳」との並べ方は、名前が決まってから考える）。

**決める期日**: サイトの最初の版（12月後半）を作る前、名前を外へ出す前。08 の文案には、ゲームの名前を入れる欄も本文もない（団体名も PO が確かめるまで書かない方針。08 §0.2）ので、博物館への最初の連絡（11月中）には名前がなくてよい。

## 4. プレイヤーの体験

### 4.1 ある一日（場面の例。店・数はすべて例）

**金曜の夜、家の PC で（夢の旅）**
1. ゲームの URL を開く。会員登録はない。金色の霞の中を、紙の鳥ましろが横切る。
2. **絵地図**が開く。国境は描かず、土地はピンと灯りだけ。いま入れるのは立山の巻だけで、ピンのまわりにほかの旅人の灯りが揺れている。ほかの場所には何も置かない。
3. 立山のピンを押すと**土地の入口**のカードが開く。巻の題、推し妖怪の白描、「夢の旅で入る」「現の旅で歩く」（家では「現地に来たら開きます」とだけ出る）、古笠からの便り。
4. 岩峅寺の箱庭（700m×400m）に、笠の見習いとましろで降りる。昼の金色の午後。境内は霧で、中には入れない。
5. 道しるべの行灯のいくつかに灯りがともっている。**白い紙の灯りは家から来た人、琥珀色の灯りは現地で灯した人**のもの。誰の灯りかは分からない。近づくと、決まった言葉から選んだ置き手紙が読める（例: 「ここで耳を澄ますといい」）。よく歩かれた道は、うっすら明るい（足あと）。
6. 墨のにじみ（気配）に近づき、指を置いて**耳を澄ます**。光蔵坊の白描の姿が浮かび、台本の会話で悩みごとが始まる。悩みをほどくと、伝承の札が1枚開き、曼荼羅帳に白描のピースが入る。
7. 駅に近い道の脇に、縁台と行灯の**休み処**がある（看板やロゴはない）。触れると札が出る:「協力先 ―（例）麓の茶屋。現地で立ち寄ると、ここでしか出ない供物がもらえる。買い物はしなくてよい」。家では供物はもらえず、何があるかが分かるだけ。
8. 帰りぎわに、自分もこの道しるべに灯りを一つ置く。明日以降、ほかの人の箱庭にも一つ増えて見える。

**春、立山へ行く（現の旅）**
1. 岩峅寺の駅で、スマホで同じゲームを開く。引き継ぎコードで PC の続きが入っている。土地の入口の「現の旅で歩く」が明るい。
2. 素の地図に札が浮かぶ。夢で光蔵坊に会った地点で立ち止まると、**色のついた本当の姿**で現れる。【創作】「夢で見た顔だな……本当に来たのか」。曼荼羅のピースに色が入る。
3. 協力先の休み処（実在の店）に立ち寄ると、その土地の供物がもらえる。買い物は条件にしない。物語を進めるのに寄る必要もない。
4. 地点に灯りを置くと、**琥珀色の灯り**になる。家から来た人たちが、それを見て行ってみたくなる。
5. 帰りの電車ではましろが眠っている（操作できない）。家に着くと、曼荼羅帳の巻末に日付入りの旅印が押されている。

**秋、ゲームの中の祭り**
- 土地ごとに年に数回、**ゲームの中だけの創作の祭り**（例: 「灯り市」）がある。期間中は、みんなが置いた灯りが土地全体の目標に向けて集まり、目標に届くとその土地の箱庭が「祭りの夜」の見た目になり、妖怪たちが集まる特別な会話が開く。
- 協賛した地元の店の名前は、祭りの終わりの「お礼の札」に並ぶ。遊んでいる途中には出てこない。
- 実在の祭礼・宗教行事は、ゲームの祭りにしない・重ねない。その日は周辺を「お休み」にする（04 §2.7）。

### 4.2 二つの旅と「土地に入る」

- 一つの土地に、入口が二つある。**夢の旅＝家から入る3Dの箱庭**、**現の旅＝現地の GPS の地図**。どちらも同じ妖怪・同じ地点・同じ物語のデータを使う。
- 二つの旅のルール（最初に公開して、後から削らない）は**ゲーム全体のルール**として、どの土地にも当てはめる。**正本は 02 §4.4**（4つ。05 §3.1 の3つに、04 §1.1 と同じ4つめを足したもの）。サイト・アプリ・この文書では、次の文を一字一句そのまま使う。
  1. 家の遊びを不利にして現地へ行かせるのではなく、現地で上乗せする。
  2. 物語の本編は、現地に行かなくても最後まで遊べる。
  3. 現地でしか手に入らないのは「色・語り仲間とえにし・旅印・その場でしか聞けない台詞」。
  4. 一度配ったものは、後から取り上げない。家でできることは、控えめに始めて広げる方向にだけ動かす。
  5. （案。PO の確認待ち）お金で家と現地の差を埋めない。色・旅印・えにし・供物・物語の先読みは、どんな形でも売らない。
- 5つめを足すかは §10 #3 で決める。あわせて、3つめに「協力先の供物」を入れるか（04 §3.8 の表には入っている）も決める。入れるなら、05 §3.1 と 02 §4.4 も同じ文に直す。それまでは、画面の文は上の正本のまま。
- 「いろいろな土地に入れる」は、主に夢の旅の楽しみになる。遠くに住む人は家から複数の土地を旅し、行けた土地だけに色が入る。帳を開くと、土地ごとの頁に「白描の土地」と「色の入った土地」が並ぶ。これが、次の土地へ行きたくなる理由になる。
- **ほかの人がいなくても遊べる**。灯りや集まりは上乗せで、面白さをそこに頼らない。

## 5. 土地＝ワールドの仕組み

### 5.1 一つの土地の中身

いまの地域パック（`apps/yokai-game/src/core/region-pack.ts` と `src/data`）を土台に、次のものを一式で持つ。

| 中身 | 例（立山の巻） |
|---|---|
| 箱庭（夢の旅の3D） | 岩峅寺の 700m×400m。数百m四方まで。街全体の複製にしない |
| 現地の地点（現の旅） | 箱庭と同じ地点の実際の緯度経度。お休みの範囲（境内など）と予備地点 |
| 推し妖怪と物語 | 光蔵坊ほか。章・悩みごと・伝承の札（監修の状態つき。02 F-71） |
| 巻の題 | 「白い曼荼羅帳」（仮） |
| 範囲の層 | §5.2 |
| 協力先の枠 | 休み処・供物がもらえる場所（02 F-72） |
| 祭りの暦 | ゲームの中の祭り（創作）の時期と、実在の祭礼で「お休み」にする日 |
| 出典とクレジット | © OpenStreetMap contributors／地理院タイル（標高）を加工して作成、監修者、協力先、作り手 |
| 状態 | 準備中／噂／開いている／閉じた |

### 5.2 範囲の層（仕組みで守る）

箱庭にも現地の地図にも同じ層を持たせ、置いてはいけない所には、データを作るとき・読み込むときの点検で**置けないようにする**。いまの `restZones` と `Spot.placeKind` を広げる形で作る。

| 範囲 | 置けるもの | 置けないもの |
|---|---|---|
| お休みの範囲（境内・ゆかりの地点・布橋のまわり、とそのまわりの余白） | 何も置かない。霧だけ | 妖怪・灯り・置き手紙・休み処・協賛の名前・出し物 |
| 物語の範囲（妖怪の地点のまわり） | 監修済みの妖怪と札、灯り、置き手紙 | 休み処・協賛の名前・出し物 |
| 道と広場（歩道のある道・広場・公園） | 灯り、置き手紙、のちに審査済みの出し物 | 住宅の前、私有地、学校 |
| 協力先の地点（店・駅・案内所・施設） | 休み処、供物の出どころ | 看板、遊びに割り込む表示 |

余白の距離は土地ごとに決める（いまは数値を決めていない）。

### 5.3 土地を開ける条件・閉じる条件

土地は「準備中 → 噂 → 開いている」と進む。**次がすべてそろうまで開けない。**

1. 物語が、少なくとも序章と1つの章まで、家だけで最後まで遊べる。
2. 札がすべて「監修済み」。了承が要る札は了承済みか、外してある（F-71）。了承の前は社寺名と由緒を出さず「この地点」と書く（04 §5.2）。
3. 箱庭が境内の外の公道・広場だけで作られ、社殿・鳥居・宿坊・個人の家を写していない。
4. 範囲の層の点検が通っている（休み処が境内や物語の地点と重なっていない）。
5. 土地の持ち主・管理者が、地点の除外・時間帯の制限・表記の修正を申し出る窓口が公開されている。
6. 地元の窓口（自治体・観光協会など）が一つ以上ある。
7. 運営と地元の数人で試しに遊び、記録を残した。

**閉じる条件**: 監修や了承が取り下げられた、地元の窓口がなくなった、保守できなくなった。閉じた土地は絵地図から外し、プレイヤーの帳の記録は残す。

立山の巻は、3月の現地テストまでは「テスト版」として、05 §7 の段取り（監修者が決まらなければ「監修前の試作」と明示）に従う。上の条件は一般公開のときに当てはめる。

### 5.4 土地の増やし方

1. **1巻目: 立山（運営が作る）**。3月の現地テストまで、05 §6 のまま。
2. **2巻目: 3月のテストの後に決める**。候補はまだない。高岡市は PLATEAU が整備済みなので箱庭を作る仕組みの検証には使えるが、巻にするかは物語・監修者・地元の窓口しだい。**2巻目は、土地ひらきの協定（制作の委託）が決まってから作る**。運営の持ち出しで空の土地を増やさない。
3. **その後: 協定先と共作**。自治体・観光協会と協定を結び、制作キット（素材・テンプレート・宗教施設と伝承のルール入りのガイドライン）を使って、伝承の調べ物と地元の調整を一緒に進める。
4. **伝承に触れるもの（妖怪・物語・札）を作るのは、運営・協定先・監修者だけ**。一般の作り手が関われるのは、伝承に触れないもの（§6.3）に限る。

「巻を増やす」より「1巻を濃くする」を優先してよい。位置情報のゲームは、土地が空っぽだと続かない（00 §5）。

### 5.5 準備中の土地の見せ方

- 2巻目が決まるまで、絵地図には立山しか置かない。
- 2巻目が決まり作り始めたら、霞の中にぼんやりしたピンを出し、「噂の地」とだけ書く。古笠の便りで噂だけ届く（【創作】例:「北のほうの湊に、話し好きの何かがいるらしい」）。入れない。日付は約束しない。

### 5.6 ほかのプレイヤーの見え方

段階を分けて足す。どの段でも次を守る。
- 現実の位置の履歴や座標をサーバーに残さない（F-52）。
- **灯り・足あと・訪問数は、匿名 ID を付けずに送る。セーブデータとは結びつけない。** 送るのは「どの地点（または道の区間）で、どの日に、家か現地か」の数え上げだけ。引き継ぎ用のセーブデータ（匿名 ID ごと）には、日付つきの旅印と「現地で得た」の印が地点ごとに入るが、これは本人の帳を戻すためだけに使い、灯りや訪問数の集計には使わない。

- 数は「たくさん」「少し」のように程度で見せる。人の少ない土地がさびしく見えすぎないように、また人を推し量れないようにする。
- 誰の灯りかは結びつけない。
- 灯りは「供える」「奉納する」と言わない。お休みの範囲のまわりには出さない（範囲の層で止める。§5.2）。

## 6. パートナーの関わり方

### 6.1 ゲームを壊さない入れ方（原則）

パートナー向けのページにそのまま公開し、契約にも書く。

1. **本編を進めるのに必須にしない。** 協力先の地点や品がなくても、物語は最後まで遊べる。協力先の供物は本編の進行に使わない。
2. **遊びの途中に割り込まない。** 画面をふさぐ広告・動画広告・ポップアップ・バナーは出さない。会話・出会いの途中には何も出さない。
3. **協賛が出るのは3か所だけ**: 休み処の札（触れたときに出る画面の文字）、遊び終わりの「お礼の札」、支度＞クレジット。帳（曼荼羅帳）の中には載せない。協定先（自治体・観光協会。巻の制作の委託元）の名前も協賛と同じに扱い、お礼の札と支度＞クレジットにだけ出す。土地の入口（B2）に出すのは、了承を得た監修の表示だけ。
4. **境内とゆかりの地点、物語の地点に出さない。** 範囲の層（§5.2）で置けないようにする。宗教行事に協賛名を付けない。
5. **授与品に似せない。** 協賛の品・グッズに、朱の印と墨書きの組み合わせ、お札・袋・紐の形を使わない。旅印と現地でしか得られない物は、売らない・譲れない・トークンにしない。
6. **箱庭に看板を立てない。** 休み処は「縁台と行灯」の共通の形で置き、店の名前は触れたときの札にだけ出す（06 §4「窓・戸・看板を作らない」）。家の箱庭では、物語の地点から離れた道沿いにだけ置く。
7. **妖怪に企業名や商品名を言わせない。** 好物は「昆布」のような一般の名前にし、どこで手に入るかは休み処の札で見せる。自治体の宣伝の文も、妖怪にそのまま言わせない。
8. **「協力先」「協賛」と必ず表示する。** 店の名前が出るところには印を付ける。
9. **買い物を条件にしない。** 供物は立ち寄るだけでもらえる。ゲームの中の品はお金で買えない（F-42）。
10. **子どもへの配慮。** 公開版では13歳未満に協力先の地点を出さない（方法は §10 #4）。中学生以下に向けた宣伝はしない。テストは18歳以上のまま。
11. **位置の履歴を渡さない。** 協力先への報告は、地点ごとの匿名の訪問数の集計まで（F-73）。訪問数は匿名 ID を付けずに送られたもの（§5.6）を**回数**で数え、人数では数えない。少ない週は「少数」とまとめて出す（下限の数は PO と決める）。小さな店で正確な少ない数を渡すと、来た人が誰か分かりかねないため。
12. **来訪数に応じた料金は、偽装に強い確かめ方（NFC タグか QR）を置いてから。** Web の位置は偽装できるため。

**戻し方の規則**: 協力先を入れた後のテストや聞き取りで「広告っぽい」という声が目立てば、休み処を地図と箱庭から外し、お礼の札だけに戻す。

### 6.3 作り手の「出し物」（2年目以降。条件つき）

README の「作り手が作って稼げる場」は、次の条件で後に残す。
- 開いている土地の「道と広場」の範囲に、**伝承に触れないもの**（光の作品、祭りの灯りの意匠、箱庭の飾り、アバターの笠・合羽の柄、音）だけを出せる。
- **招待制**から始め、自己申告の質問票を必須にする（お休みの範囲に置くか／実在の神仏・寺社名・祭神・授与品を使うか（使うなら差し戻し）／伝承を使うか／地元の了承／協賛を含むか／家でも楽しめるか）。不正確な申告や保守されない出し物は取り下げる。
- 06「光と霞」の色と光の決まりの要約を渡し、世界から浮かないようにする。
- 始めるのは、立山に遊ぶ人が集まってから。最初の試行は数件にとどめる。
- 他の団体のキャラクター（クタベなど）は描かない。

### 6.4 README の「社会貢献基金」

当面は外す。理由は、法人の形が決まっていないこと（08 §0.3）と、寄付先に社寺や宗教行事が入るとゲームが宗教にお金を流す形になること。残すときは「土地へのお返し」として、次の条件をそろえてから作る。
- 法人の形が決まり、外向けにどう書けるかが分かっている。
- 使い道は文化財の保存・自然保護・地元の公共に限り、社寺と宗教行事は対象にしない。
- 割合は決めない。プレイヤーの投票は、その後で考える。

それまでは、伝承に出典を付けて正しく伝えること、ライチョウを追わせないことを「土地への還し方」として説明する。

### 6.5 申し出の窓口

公開の前から、土地の持ち主・管理者が「地点の除外」「時間帯の制限」「表記の修正」を申し出られる窓口を、サイトの「土地と祈りへの配慮」のページに置く。組織のメールアドレスなどで本人確認をする。

### 7.3 1年目の見方と、受託が取れなかったとき

1年目は「収入を作る年」ではなく、**「立山という動く見本で、2巻目の土地ひらきの協定を取る年」**。

受託が1年目に取れなかったときは:
- 2巻目は作らない（運営の持ち出しで空の土地を作らない）。
- 立山の巻に章を足して、1巻を濃くする。
- 実物のおみやげを1件試す（柱3）。
- 休み処と祭りの協賛は、小さな規模のまま続ける。

### 7.4 README の6本の柱との対応

| README の柱 | 判断 | 理由 |
|---|---|---|
| 内容の販売手数料（マーケット 10〜15%） | **条件つきで後に残す**（柱7） | 伝承に触れるものを誰でも売れる場は、監修と宗教のルールとぶつかる。伝承に触れない出し物から、招待制で始める |
| イベント参加費 | **条件つきで後に残す**（現地の集まり） | 実在の祭礼とは切り離した形でだけ。1年目はやらない |
| 企業の PR・広告 | **形を変えていまやる**（柱1・4） | 画面の広告はやらない。「世界の中の休み処」と「お礼の札」に置き換える |
| 有料会員 | **やらない** | 家と現地の線引き（§4.2）を崩しやすい |
| 開発ツールの料金 | **やらない** | 地形を作るスクリプトは無償で公開する約束（ODbL）。制作キットは協定先に無料で渡す |
| 物販 | **いまやる**（柱3） | 食べ物のおみやげから。授与品の形は避ける |

### 7.5 やらないこと
画面の広告、動画広告で報酬をもらう仕組み、現地限定の物や家と現地の差を買える仕組み、旅印・供物の売買やトークン化、位置の履歴を集めて売る・分析すること、宗教行事に関わる物販や協賛。

## 11. 採らなかったことと取り入れたこと

この文書は、Claude が3つの案（「街のプラットフォームが主役」「表はゲーム、裏は街の器」「ゲームが主役」）を作り、Claude の中で4つの観点（遊びの面白さ・事業・作りやすさ・信仰と地域への配慮）から比べて、**「ゲームが主役」案を土台に**まとめた（4つの観点のうち3つが、この案を土台に推した）。実在の人による審査ではない。

**採らなかったこと**
- 開くと街が並び、街ごとの門で演目を選んでから遊ぶ形。遊び始めるまでの段が多く、PO の「普通にゲームとして」から遠い。
- 作り手の作品が、1年目から街に並ぶ形。妖怪と伝承の世界が薄まり、審査の手間が小さな体制には重い。
- サイトと名前を、プレイヤー向けとパートナー向けの二つに分けること。説明と保守が二重になる。
- 協賛を曼荼羅帳（プレイヤーが育てる帳面）に載せること。
- 灯りをその日のうちに見せること。誰がいつどこにいたかを推し量れてしまう。

**取り入れたこと**
- 範囲の層、門の審査（開ける条件）と閉じる決まり、申し出の窓口。
- 家は白い紙・現地は琥珀色の灯り、足あと、灯りの量で絵地図の明るさが変わる仕掛け。宵の集い（後で）。
- 運営の名前として AR City Vision を残すこと。妖怪に企業名や商品名を言わせない決まり。「広告っぽい」の声で休み処を外す戻し方。
- 「1年目は、動く見本で2つ目の土地の協定を取る年」という見方。2巻目は委託が決まってから作ること（§10 #7 で見直す）。
- 13歳未満に協力先を出さない約束。作り手の出し物の招待制と質問票（2年目以降）。

細かい比べ方は付録 A に残す。
